# What is SBOMVert?

SBOMVert is a web app for comparing and translating **SBOMs** (Software Bills of Materials) and
**CVE** (vulnerability) reports produced across tools- for the *same* artifact.

It is based on the research published at
[arxiv.org/abs/2510.05798](https://arxiv.org/abs/2510.05798).

## Why compare tools?

SBOM generators and vulnerability scanners rarely agree. Run two tools
against the same image and you can get:

- **Different package lists**- one tool sees a dependency another misses, or
  they name and version the same package differently.
- **Different vulnerability findings**- scanners disagree on which CVEs affect
  a package, on severity, and on whether a fix is available.

These disagreements matter for security decisions, compliance, and trust in the
supply chain. SBOMVert makes them visible so you can understand *where* and
*why* tools diverge, rather than trusting a single tool's output blindly.

## The compatibility issue

SBOMs are only useful if they can be reliably exchanged and consumed. In
practice, though, the tools in the ecosystem are not fully interchangeable, and
this creates real friction:

- **Format fragmentation.** SBOMs come in different formats (e.g., SPDX and
  CycloneDX), each with several versions and serializations. A report produced
  in one format is not guaranteed to be understood by a consumer that expects
  another.
- **Producer/consumer mismatch.** An SBOM generated by one tool may not scan
  cleanly in another. Fields a scanner relies on (pURL identifiers, versions,
  licenses) are populated differently depending on who produced the document.
- **Identifier drift.** The same package can be described with different names,
  versions, encodings, or Package URLs across tools.

The result is that swapping one tool for another- or feeding one tool's output
into the next stage of a pipeline- is rarely lossless. SBOMVert surfaces these
incompatibilities directly: by normalizing reports into a common model and
diffing them side by side, it shows exactly where formats, fields, and
identifiers fail to agree.

## How it works

SBOMVert reads SBOM and CVE reports as data, diffs them, and "translates" SBOM
documents so that they become compatible with downstream security scanners.

SBOMVert currently supports **SPDX** and **CycloneDX**.
